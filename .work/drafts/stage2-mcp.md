# Stage 2: MCP server and auth

## Summary <!-- work:summary -->
Build `packages/mcp`: a Cloudflare Worker that serves the Wayfinding MCP server at `https://poc.wayfinding.support/mcp` with the official TypeScript SDK, accepts only WorkOS AuthKit access tokens issued for that resource, provisions an account on first use, and offers coordination tools (journeys, members, roles, guides, joining, agents, projects) that step the compiled gdp-wired rules inside one Durable Object per journey before writing. No artifact content yet.

## Why <!-- work:rationale -->
Dan chose gdp-wired rules plus the MCP server first, with WorkOS for accounts, sign-in and passkeys. The PoC runs at `poc.wayfinding.support` (the old app's domain stays dark). AuthKit Staging facts: issuer and authorization server `https://welcoming-folk-53-staging.authkit.app`, JWKS `https://welcoming-folk-53-staging.authkit.app/oauth2/jwks`, CIMD and DCR enabled, passkeys enabled, default OAuth resource `https://poc.wayfinding.support/mcp` so tokens carry it as `aud`, PKCE S256, `none` client auth. Access tokens last 300 s and carry `sub` (WorkOS user id); profile details come from the WorkOS User Management API with a Worker secret `WORKOS_API_KEY`, never from the client. Hard constraints: official SDK releases pinned exactly (`@modelcontextprotocol/server` 2.4.0, `@modelcontextprotocol/client` 2.4.0 for tests), no `gate()` or `compiled()` on stored state, values below 2^53, Cloudflare account 16c42d94e589cc74c99aed7d51687cbc. Non-goals: MLS, artifact content, MCP Apps, tasks extension, deployment (done by the dispatching session).

## Acceptance criteria <!-- work:criteria -->
- mcp-auth: A request to `/mcp` without a token, with a token signed by another key, with an expired token, or with an `aud` other than `https://poc.wayfinding.support/mcp` gets `401` with a `WWW-Authenticate` challenge naming the resource metadata URL; `/.well-known/oauth-protected-resource/mcp` returns `resource` `https://poc.wayfinding.support/mcp` and `authorization_servers` `["https://welcoming-folk-53-staging.authkit.app"]`; a valid token reaches the `whoami` tool, which reports the token subject.
- mcp-eras: The same handler serves a 2026-07-28 client and a 2025-11-25 stateless client (both with the official client package), each listing tools and calling `whoami`; `wrangler deploy --dry-run` bundles the Worker.
- mcp-coordination: With signed test tokens for several people, tools create a journey (creator becomes the first person guide), list my journeys, read a journey, issue and accept an invite or join under the joining policy, change a role, give and remove guide authority, add and remove my agent, remove a member, leave, and create, join, leave and update a project; every refused case named by the rules (last person guide removal, non-guide role change, agent beyond its person, joining an invite-only journey without an invite, editing a project you are not in) returns a tool error and leaves stored state unchanged; stored journey state records the rules hash from `rules.lock.json`; no source under `packages/mcp/src` calls `gate(` or `compiled(`.
