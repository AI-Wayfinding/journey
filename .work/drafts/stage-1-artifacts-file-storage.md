# Stage 1: artifacts and file storage

## Summary <!-- work:summary -->
Deliver journey-visible artifacts and encrypted attachments in the existing private journeys. Support skill, prompt, Markdown document, image, file, data and link artifacts, free tags, append-only versions, whole-artifact comments and signed attribution. Deliver browser and CLI/MCP workflows, retain the existing read-only agent-link overview, and preserve Stage 0 controls and access. This is an implementation plan, not implementation approval or passing evidence.

## Why <!-- work:rationale -->
Ontology section 9 Stage 1 and decision 0001 D5, D8–D11, D30–D31, D34 and D38–D39 define the outcome. Amendments override earlier wording. Stage 0 is merged at 2196e368068718c8a01139568855faf99950df3e. Ontology approval remains the implementation prerequisite; document promotion does not grant it. The ontology appendix and original Stage 0 draft contain older code observations and migration promises; current code and the Stage 0 amendments establish signed public controls, current inherited access and no legacy migration.

All access and permission decisions belong in production Bend functions in packages/rules, stated in LAWS.bend and proved by PROOF.bend. TypeScript validates formats and signatures, copies named fields, encrypts, stores and transports, then calls Bend on verified inputs. Extend scripts/check-bend-boundary.mjs to cover the new decision family without weakening its Stage 0 checks. Signed public ControlProof is the only authority: encrypted artifact payloads and blob bytes carry private content, never actions or grants. A hostile or careless caller must not forge another author or version writer, gain writes from guide authority, exceed inherited agent access, replay stale edits, attach another journey's blobs, use an unfinished upload, bypass size checks by lying about size, or commit after downgrade, removal, expiry or pending rotation. URL and data rendering must not cause server fetches, script execution or automatic network requests. Old downloaded keys and content cannot be recalled.

There is no production data to migrate: journeys were purged and remaining fixtures are test data. “Migrate D8 categories” means a mapping in new-artifact creation/import code and tests, not a storage migration, historical rewrite, bootstrap trust path or migration checkpoint. Internal recovery records remain separate from user artifacts.

Out of scope: projects; author-private artifacts and invisible storage; interview relationships and subject access; rounds and contribution confirmation; HTML/applet execution or stores; public journeys, listing, joining-policy activation, cross-journey sharing or visibility conversion; shared-read refactoring, client/link parity and drops. General hardening, account recovery changes, historical agent key delivery and security certification remain separate backlog. Preserve the app header/footer and existing person controls. No deploy, bucket provisioning, package publication or remote actions are part of execution evidence.

## Decisions taken

These choices resolve the technical questions in ontology section 9 without reopening Dan's product decisions. The lead should review them before implementation.

1. **Active types:** `skill`, `prompt`, `document`, `image`, `file`, `data`, `link`. Reserve `html`, `applet`, `interview` and `sensemaking-document` for later stages and refuse their creation now; do not advertise their later behavior. Documents are Markdown. Skill packages contain required `SKILL.md` text and optional named attachments; prompts contain required prompt text and optional named attachments. No ZIP extraction, dependency execution or remote package fetching. Free tags are case-preserving strings, deduplicated by exact value; suggested tags are not a permission or closed taxonomy.
2. **Category mapping:** note, decision, question, learning, tension, practice, success and resource become document plus the same suggested tag. Position becomes document plus `position`; interview becomes document plus `interview` (no private/interview relationship); lesson becomes document plus `lesson`. Other category strings become document plus the original string as a tag. Preserve supplied tags without duplicate insertion. `recovery` is not mapped or shown in artifact lists, searches, counts or links. Mapping is only for new import/create inputs; no legacy journeys are converted.
3. **Schema and identity:** artifact ID is stable across versions; each version and comment has a fresh ID. First committed creator is immutable author (D38); each later version/comment records its actual signer separately. Type is fixed at creation; title, content, free tags and attachments are versioned together. A version names the current predecessor; concurrent stale edits conflict rather than silently winning. Comments target the stable artifact, optionally cite a version for context, and are whole-artifact comments, not passage annotations. Any currently read-write member may edit/delete/comment on an ordinary journey artifact, not only its author (D5); guide authority adds nothing. A comment is immutable and removed only by whole-artifact deletion in this stage.
4. **Authority format:** add versioned artifact create/version/comment/delete ControlProof actions to the existing signed chain. Their public projection contains only routing/authority fields: stable artifact and version/comment IDs, predecessor, immutable author, actual actor, referenced blob IDs, epochs, byte counts and ciphertext digests. Titles, type-specific content, filenames, MIME types, tags, notes and comment text stay encrypted. Bind each proof to its exact encrypted payload, journey, chain position and signer; do not add an independently authoritative encrypted record. Extend keyed reading for these payloads without weakening `control.labels` restrictions for existing controls. Public content metadata is allowed for these journey-visible artifacts; this storage is explicitly unsuitable for Stage 3 existence secrecy. Agents may sign artifact actions under D34, but must not thereby gain permission for person/guide controls. Keep control-chain sequences distinct from existing ordinary record reservations.
5. **Files and storage:** use a private Cloudflare R2 bucket binding `ARTIFACT_BLOBS`, with server-mediated authenticated uploads/downloads, never public URLs or reusable bearer read URLs. Local test configs use local R2. No bucket creation or deployment is required by the plan. Store binary AES-GCM ciphertext, not base64 JSON or data URLs. Encrypt in the browser (and in the Node client before upload) with a fresh random 12-byte nonce using the current journey epoch key; authenticate journey/blob ID, epoch and raw byte length as associated data. Private metadata stays in encrypted artifact payloads. The server checks decoded binary length and ciphertext digest; readers check decryption, authenticated metadata and referenced digest.
6. **Limits:** “25 MB” means at most 25,000,000 raw file bytes, inclusive, before encryption, not 25 MiB or JSON size. Zero-byte files are valid. Ciphertext is exactly raw length plus the 16-byte AES-GCM tag; nonce travels in the file descriptor. Count streamed bytes independently of Content-Length and reject the first byte above the limit, truncated data and descriptor mismatches. Keep the 1 MiB JSON record/payload cap; it is not the upload cap. Allow at most eight distinct attachments per version, each individually limited; a file/image artifact has exactly one primary attachment included in those eight. Skill/prompt/document/data/link artifacts may have up to eight. Filenames are display labels and safe download names, never filesystem or bucket paths. Reject duplicate IDs, traversal package paths, and unknown caller fields before storage.
7. **Upload lifecycle:** authenticated current writers stage blobs under server-generated journey-scoped IDs. Stage for at most one hour; upload grants no committed artifact. Bind staging ownership to the uploader; only that actor can consume its staged blobs. A later writer may reuse an already committed blob only from an undeleted version of the same artifact; arbitrary cross-artifact references are refused. This lets editing retain attachments without granting access through untrusted blob IDs. Recheck current Bend access, supported version, epoch and pending rotation at begin, upload completion and artifact commit. A blob is readable only after an authorized proof commits its reference; retain references from all undeleted versions. R2 and Durable Object storage are not one transaction: upload to R2 first, then atomically commit verified proof/index/reference state in the journey object. Failed/conflicting commits leave expiring staged bytes, never partially visible artifacts. Provide idempotent retry by exact committed proof identity; a different replay is a conflict. An alarm retries garbage collection, never deletion of referenced objects. Download rechecks current access; removal blocks future requests, not an already delivered stream.
8. **Deletion/retention:** whole-artifact deletion is a signed tombstone, hides all its versions/comments/attachments from ordinary views and downloads, and cannot be undone in Stage 1. Keep signed proof history and encrypted metadata history for integrity/export, explicitly labelled retained history, not secure erasure. Queue blob deletion when no undeleted artifact version references it; retry safely and never delete a live reference. Export contains surviving referenced blob ciphertext and descriptors plus signed proof history, encrypted payloads and wraps in a versioned archive; it explains deleted blob unavailability. Previously downloaded copies remain outside server control. No historical archive migration or new browser import UI is required.
9. **Images and downloads:** inline preview only validated PNG, JPEG, GIF and WebP bytes; MIME declarations/extensions alone are not validation. SVG, HTML, executables and other formats remain downloadable file content, never inline active content. Serve downloads with safe Content-Disposition, nosniff and no-store; create/revoke local object URLs after authenticated decryption. Do not permit active Markdown HTML or automatically load remote images.
10. **Data views:** support JSON, CSV, TOML, YAML and SQLite explicitly. Browser-only bounded read views: first 100 rows and at most 100 columns for tabular data, a text/tree view bounded to 1,000 displayed nodes and 100,000 displayed UTF-8 bytes for structured data, with clear truncation/errors and original-byte download. JSON/TOML/YAML parsers do not construct executable objects or custom tags; CSV treats formula-like cells as text. SQLite uses a browser-local read-only engine, schema/table browsing and generated SELECT queries only, no user SQL, extensions or external file/network access. Parsing accepts at most 25,000,000 input bytes, uses at most 128 MiB worker memory where the engine exposes a limit, and terminates its worker after ten seconds or viewer cancellation; oversize structures, excessive nesting (over 64 levels) and YAML alias expansion fail to a raw-download fallback. Large parses run off the UI thread and can be cancelled. Unsupported formats remain downloadable with a clear “no data view” message; no applet runtime or general query service.
11. **Links:** required absolute `http:` or `https:` URL plus supplied title, summary and notes; reject credentials, control characters and non-web schemes. Neither server nor preview code fetches the URL or supplies summaries. Show inert text until the viewer deliberately opens it; external opening uses noopener/noreferrer. No remote images or unfurling.
12. **Compatibility and interfaces:** use Stage 1 client/interface version 0.1.5 and artifact format capability `artifact-v1` in addition to `control-proof-v1`. New journeys require it; existing Stage 0 test fixtures may raise their signed minimum before the first artifact action, but there is no data migration. Unsupported readers fail closed with an update message before partial content. Browser and CLI/MCP get create/list/filter/search/show/versions/comment/edit/delete and attachment upload/download using existing access; CLI file arguments are explicit local inputs and MCP uses explicit paths, not automatic remote fetching. Keep existing text-command aliases mapped to document artifacts with suggested tags. Agent links remain read-only: adapt only their existing overview/paged representation to artifact text/metadata and update gates. No new link search/show/download routes, drops or parity contract; report that attachments require the member interface. Deliberate server decryption through live links stays labelled.

## Current code observations

Read docs/ontology.md, decision 0001 and docs/journey-protocol.md in full. Inspected Stage 0 draft/spec, package scripts, storage routes/configuration, core item/envelope/control/archive code and interface call sites. These are source observations, not passing Stage 1 evidence.

- `packages/core/src/items.ts` uses permissive `itemType`, `replaces` chains and version-bound comments. `itemVersions` drops orphan edits. `packages/core/src/envelope.ts` encrypts JSON only; there is no binary blob format.
- `packages/core/src/controlProof.ts` signs the only public action, verifies ciphertext/position/signature and calls shared rules. Existing private control payloads accept labels only. Stage 1 needs a separate strictly parsed private-content payload, not actions smuggled through labels.
- `packages/server/src/enclave.ts` persists verified control authority, serializes operations, calls Bend for current reads/writes/version/admission and blocks writes while rotation is pending. Records are SQLite JSON envelopes. `packages/server/src/index.ts:379–390` caps plaintext JSON at 1,048,576 bytes and validates ciphertext length. Neither production nor local Wrangler config has a blob bucket.
- `packages/web/src/journey.ts` and `packages/client/src/journey.ts` still write ordinary item/comment ciphertext through `/records`. The client duplicates some grouping. Stage 1 replaces active artifact paths without undertaking Stage 7 shared-read refactoring.
- `packages/server/src/agentLink.ts` groups text items and suppresses recovery. It has no attachment service. `packages/core/src/transfer.ts` verifies legacy signed-log archives, while browser export uses verified Stage 0 controls; new archive support must explicitly verify public proofs rather than treating reconstructed entries as independently signed legacy logs.
- Package tests use Vitest, workerd and browser runners; Playwright and client local-server tests share port 18787 and must run serially. Builds generate ignored outputs. Use `scripts/bend.mjs` because work_verify runs with HOME unset.

## Criterion homes and proof contract

Commands execute from the repository root with dependencies already installed. Each command expects exit 0 and a non-empty output floor. Tests must make real assertions; markers alone are not proof. Evidence may write only ignored build/cache/scratch outputs, never tracked sources, manifests or locks. Mutations run in disposable ignored copies, must reach assertion/proof failure rather than missing-module/syntax failure, and restore no production file because production files were never changed. ## Scope overlap review

`artifact-contract` establishes shared contracts and version/fixture alignment before later nodes. `blob-crypto` then edits the core index. `artifact-storage` extends rules only after both core nodes. Browser/client work can run alongside each other, but local test commands must not share port 18787. `data-views` follows browser work because both own rendering. `integration` follows both branches. Shared `package-lock.json`, `packages/web/package.json` and `packages/web/src/journey.ts` are intentional serialized write points, not independent parallel scopes; the validator's concentration advisories are accepted for that reason. Broad server source ownership stays in artifact-storage because route, typed message, durable state and link updates form one storage transaction boundary. No node may widen touches without lead review.

## Worker boundaries

### artifact-contract

Define strict artifact/version/comment/delete records, signed public projections and replay with encrypted content payloads. Preserve exact legacy category mapping as a new-input helper and recovery separation; no migration. Extend ControlProof/log state and Bend operation constructors to handle agents' content actions while retaining person-only control rules. Implement predecessor conflicts, immutable author/type, named-field adapters and descriptor validation. Document the wire contracts, archive format and minimum/capability boundary. Add laws for no content action without current write access, immutable creator attribution, real actor attribution, no stale predecessor, no cross-artifact reference, no resurrection after deletion and reference transitions retaining live versions. Prove the actual production functions, not disconnected examples; preserve Stage 0 law meanings. Add format, forged attribution, unexpected-field, replay/conflict and archive tampering tests. Only symbolic authority/reference proofs are claimed, not crypto certification. Coordinate new blob descriptors with the next node's implementation through this documented contract. Own initial 0.1.5 core/client/interface version, capability, dependency and lock alignment and shared fixture header changes so downstream node evidence can run independently. Manifest/lock overlap with data-views and integration is deliberately serialized. Existing Stage 0 tests remain regression scenarios, not migration work.

### blob-crypto

Implement portable binary encryption/decryption and descriptor/digest checks in a new core blob module using Web Crypto only. Test zero, limit-minus-one, exact 25,000,000 and limit-plus-one raw bytes, nonce/AAD tampering, truncated/oversized ciphertext and wrong digest/epoch/journey. JSON and binary limits are distinct. This node depends on descriptor contracts and owns no access policy or server transport. Run the same focused suite in Node, workerd and browser.

### artifact-storage

Depend on contract and binary crypto. Add R2 bindings in production and local test configs, typed binary routes, journey-owned staging/reference state and alarm cleanup. Add any new lifecycle allow/deny functions, laws and proofs in packages/rules; callers must not write TypeScript permission decisions. Use current signed proof authority and serialized journey state to recheck access/epoch/version at every transition, including concurrent downgrade, removal, rotation, stale commit and read/delete races. Server-generated bucket keys never contain caller filenames. Authenticate before accepting bytes; bound real streamed bytes and validate the complete digest before marking staged upload complete. Commit only fully uploaded, uploader-owned, same-journey blobs; rejected batches change nothing visible. Cleanup after crashes is idempotent and cannot remove referenced blobs. Retain proof history, hide deleted artifacts and prevent deleted blob reads; expose surviving ciphertext for export without decrypting private content. Adapt existing agent-link overview only, keeping read-only access and recovery suppression. No new link read surface. Update server route documentation. Test with local R2/workerd, not mocks alone or a live bucket.

### browser-artifacts

### data-views
