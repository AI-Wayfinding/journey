# Stage 1: coordination rules in gdp-wired

## Summary <!-- work:summary -->
Write the rewrite's coordination rules as gdp-wired models in `packages/rules`: journey membership and authority (roles, guides, joining, removal, agents, agent cards, grants), shared work (projects, shared-artifact metadata and versions, tasks), and personal groups with copy and move. Each model compiles to `generated/<name>.js`, proves every step law from any state, and has broken variants that must fail.

## Why <!-- work:rationale -->
The Durable Object and the local proxy step these rules before every coordination write (stage 2 and 3), so they must exist and be proved first. Dan decided the rules are written straight in gdp-wired with a plain-language comment per law, and he reviews them in stage 7 (no pi-intent, no approval step now). Rules read only coordination state: they never read artifact content. Host code keeps signatures, hashes, key wrapping, time comparison results and list order, and passes their outcomes in as inputs. Values stay below 2^53: host encoders intern ids to small integers. Non-goals: the server, MLS, network code, encryption, Lean builds.

## Open decisions <!-- work:decisions -->

## Acceptance criteria <!-- work:criteria -->
- journey-authority: A `journey` model (or a small family of models) covers membership kinds person and agent, content roles read-only and read-write, guide authority separate from role, joining policies request, open and invite-only with a default role, invites, removal and leave preserving the last person guide, an agent's authority equal to its live adding person's, removal of a person removing their agents and ending their grants, agent card limits signed once by the person with effective capability = person capability AND card limit AND both live, and grants (issue needs the grantor to hold the capability and be live; use needs live, unexpired, uses left; revocation terminal; no re-delegation). Every step law passes `proveSteps(..., {from: 'any'})` with `proven && checked && !assumes`, each law has a broken variant that is refused, and the compiled module matches the model.
- shared-work: A `project` model covers joining, leaving, purpose and state edits by project members (getting started, active, looking for others, archived; archived can reopen); an `artifact` metadata model covers create, new version, rename and delete by members with write authority, an immutable creator and type, and version numbers that only increase; a `task` model covers open, claimed, in-round, done, expired and cancelled, a round only while rounds used are below the cap and the deadline has not passed, and terminal states that never change. Same proof, broken-variant and compiled-module requirements.
- personal-groups: A `personalGroup` model admits only its owning person, that person's devices and agents; a `transfer` model allows copy only when the actor is live in source and destination with read in source and write in destination, and move only when copy is allowed and delete in the source is allowed. Same proof, broken-variant and compiled-module requirements.
- rules-gate: `npm run check:rules`, `npm run typecheck` and `npm test` pass at the root with every model listed in `src/models.ts`, and no file under `packages/rules/src` calls `gate(` or `compiled(`.
